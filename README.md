# 中国大陆节假日数据 · calendar-holidays

个人维护的年度放假、调休补班数据，依据国务院办公厅公开通知整理：历史年份人工核对，新年度可由下述自动同步流程录入。**非政府或官方服务，不代表发布机关；具体安排以官方最新通知为准。** 本仓库不预测尚未公布的年度安排，不适用于各地额外假期、少数民族节日、企业排班或个人休假。

目前发布 **2016—2026 年**，共 11 个年度文件。放假区间包含公告所述连休周末，普通周末不单独列出。这里的 `isOffDay` 表示通知安排的放假日，不表示每一天都是具有相同工资规则的法定节假日。

## 使用

公开仓库的 `index.json` 为索引；`years/2026.json` 为年度文件。可以通过 GitHub 的 Raw 地址下载，无需服务器、账户、Token 或收费 API。网络不可用时，客户端应使用本地缓存。

索引中的每个年度条目包含 `version`、`path`、`sha256`。路径相对于仓库根目录；校验值按文件的原始 UTF-8 字节计算。年度 JSON 包含版本、发布状态、时区、官方来源与日期列表。示例日期条目：

```json
{"date":"2026-10-10","name":"国庆节调休补班","isOffDay":false}
```

推荐客户端每 7 天检查一次索引，仅版本或校验值变化时下载年度文件。未出现在索引中的年份视为未发布，不能按“没有假期”处理。HTTP 错误、格式错误、校验失败均不得覆盖有效缓存。下载索引与文件期间如发生更新，可延迟重试；不要绕过校验。SHA-256 用于发现内容不一致，不等同于数字签名。

## 每年怎样维护

只修改 `plans/年份.json` 中的七类假期区间、补班日期及公告来源；生成脚本会展开每一天并更新索引，无需逐条录入几十个日期。

1. 官方公告公布后，创建草稿：`python3 scripts/manage.py new 2027`。
2. 根据官方公告填写 `sources`、`holidays`、`workdays`，核对全部区间和补班日期。
3. 将 `status` 从 `draft` 改为 `published`；填写实际维护日期 `updatedAt`；初次版本为 `2027.1`，后续修订依次为 `2027.2` 等。
4. 运行下面的生成与校验命令，然后把维护文件、年度文件、索引一起提交。生成器也会回填上一年 12 月受影响的日期；若上一年度已发布，更新其修订号和维护日期，随本次提交一起发布。
5. 查看 GitHub Actions 是否通过，再核对 Raw 地址是否能下载。校验不代替人工核对官方公告。

```sh
python3 scripts/manage.py build
python3 -m unittest discover -s tests -v
python3 scripts/manage.py check
```

草稿不会进入年度下载目录或索引。离线维护脚本 `manage.py` 不抓取第三方节假日 API，也不会发布猜测的数据。若公告修订，更新来源、日期、版本号和维护日期，再重新生成；若资料未齐，保持草稿。

## 自动检测与更新

`Sync official holiday notices` 工作流每天 **北京时间约 09:17（UTC 01:17）** 在 GitHub 托管的运行器执行；也可在 Actions 页面选择 `Run workflow` 立即检查。无需自己的服务器、Mac 开机、GitHub 私人 Token 或付费节假日 API。

流程：

1. 从中国政府网官方政策文件检索服务发现当年与下一年的年度通知及假期/放假相关调整通知。
2. 仅访问预设官方域名，读取公告正文，核对标题、年度、文号及发布日期。
3. 解析完整七类假期及补班日期，校验天数、日期范围、周末补班和冲突。只有尚不存在且没有其他调整通知的新年度，才会自动生成并发布。
4. 生成年度 JSON 和校验索引；涉及上一年 12 月时自动提高上一年度修订号并回填日期。所有测试和生成一致性检查通过后才提交到 `main`，不会强制覆盖其他提交。
5. 已有年度数据变化、临时调整/延长、正文结构变化或不能确定的内容，写入 `automation/reviews/`，不直接修改原年度安排。检查 Actions 运行摘要和该目录，人工核对来源后用上面的维护步骤修订；处理完可移除对应待核对记录。

网络异常、官方检索异常或测试失败时，工作流失败并保留 GitHub 上已发布的数据；可在 Actions 页面查看原因或重新运行。相同公告正文不会重复发布或重复建立待核对记录；普通无变化检查不产生提交。`automation/state.json` 保存已处理公告摘要，以及每月一次的健康记录；月度健康提交用于避免公开仓库长期没有活动而导致定时工作流被停用，不改变节假日日期。

GitHub 定时任务可能延迟，因此这是每日检查而非秒级实时更新；官方检索也可能存在收录延迟。若工作流被平台、账号或仓库设置停用，需在 Actions 页面重新启用。客户端仍按索引缓存周期获取数据，也可在应用设置中手动检查更新。

`Validate holiday data` 工作流仍以只读权限在提交和 PR 时校验；自动同步工作流只有本仓库内容写入权限，用 GitHub 提供的短期 `GITHUB_TOKEN` 提交数据和健康记录，不修改工作流或权限设置。

## 免费运行与费用保护

两个工作流都只允许在 `zbuzhi/calendar-holidays` 公开仓库运行，固定使用 GitHub 标准 `ubuntu-24.04` 运行器，单次任务最多 5 分钟。仓库改为私有或复制到其他仓库后，任务会跳过，不分配运行器；恢复前应重新确认计费规则。

自动检查每天一次，不配置付费大规格运行器、矩阵或缓存，也不上传 Actions 构建产物；报告通过运行日志、运行摘要及仓库内待核对记录查看，避免产物持续占用存储。验证任务遇到同一分支的新提交会取消旧任务。

工作流限制不能代替 GitHub 账单限制。已核对账号级 Actions 产品预算为 **$0**，预算列表显示 **Usage blocked**，本仓库也受该账号预算约束。可在 GitHub 的 **Settings → Billing and licensing → Budgets and alerts** 中复查 **Stop usage when budget limit is reached**，不要将停止使用改为仅提醒。免费额度内的使用不受付费预算影响；超出预算的付费使用应被阻止。以 GitHub 当前计费及预算规则为准；预算创建前的用量不受新预算追溯限制。以后新增工作流或更改仓库可见性、运行器、存储设置时，应重新检查费用保护。

历史调整与口径：

- 2019 年五一采用[3 月 22 日修订通知](https://app.www.gov.cn/govdata/gov/201903/22/436883/article.html)，放假 5 月 1—4 日，并补入 4 月 28 日、5 月 5 日上班。
- 2020 年春节依据[延长通知](https://app.www.gov.cn/govdata/gov/202001/27/453442/article.html)计到 2 月 2 日，原 2 月 1 日补班取消；不包含地方另行规定的延迟复工时间。
- 2024 年除夕 2 月 9 日仅为鼓励结合带薪年休假休息，不标记成全国统一假期。
- 联合假期以“中秋节、国庆节”或“国庆节、中秋节”合并命名，不重复记录同一天。
- 次年元旦涉及的上一年 12 月日期会自动回填到上一年度文件，并附上次年公告来源。例如 2018 年文件也含 12 月 29 日补班、12 月 30—31 日放假；只下载该年文件就能正确计算年底工作日。
- 年度文件同时保留本年度元旦公告中前一年 12 月的日期，便于跨年查询；不同年度文件中的重复日期必须一致。上述表格包含本年年底为次年元旦安排的休息日期，因此不能直接与单份年初公告的放假天数相加结果比较。

数据来自官方公开日期事实，不依赖 Timor 或 holiday-cn 数据。本仓库原创代码、说明及可受保护的整理内容采用 [MIT License](LICENSE)，允许商业使用与修改分发，并须保留许可声明；不对行政文件或日期事实本身主张排他版权。许可不意味着官方背书，也不保证数据永远完整、正确或服务永久可用。
